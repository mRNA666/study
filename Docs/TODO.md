## 已知问题（下次优先解决）

### 1. 每挖一次卡顿一下

**现象**：点击左键挖洞，画面明显停顿一下。

**原因**：`ADigVolume::DigAt()` 每次都调用 `RebuildMesh()` 做**全量重建**。

- 1 m³ 方块 / 2 cm 步长 / 20 个左右的洞 → 约 4 万个三角形
- 实测 `build=` 约 30~45 ms（8 线程并行，`bParallelCompute=true`）
- 60 fps 的帧预算是 16.7 ms → 必然掉帧

**方向**（按代价从低到高）：

1. **脏区域重建** —— 只重建被挖到的分块。挖 10 cm 半径的洞只涉及约 630 个三角形，约 0.4 ms。
2. **降低采样精度** —— `SampleStepCm` 2 → 3，面数降一半以上，但表面手感变糊。
3. **异步重建** —— 把重建丢到后台线程，晚 1~2 帧替换网格。

**先做哪个**：先量。用现有日志的 `build=` 和点击手感的差异，确认卡顿的量级和来源。

### 2. 挖多次之后出现悬空的小碎块

**现象**：连续挖很多次后，石头上或空中残留一些孤立的小碎片。

**原因**：SDF 减法 `max(石头, -球)` 只负责"减掉球内的部分"。
如果某次挖洞把一小块石头和主体切断，那块就变成**孤立的壳**。
Marching Cubes 照样会生成它（它只认零等值面，不管连通性），
而 UE 不会自动把它变成可掉落的物体 —— 它就那么浮着。

**方向**：

1. **连通性检测** —— 重建后按三角形做连通分量分析，保留最大的一块，
   其余当成"掉落物"生成物理碎块。`FDynamicMesh3` 应该有组件分割的工具，需要查 API。
2. **先不管** —— 给它们加简单物理让它们掉下来，视觉上反而像挖下来的碎石，合理。

## 环境备忘（踩过的坑）

- **编译前必须关掉编辑器**，否则 `LNK1104`（DLL 被占用，链接器写不进去）
- **改了头文件 → Live Coding 打不了补丁**，必须完整编译（UHT 要重新生成反射表）
- **Live Coding 会骗人**：报 "no code changes detected" 不代表代码进去了，要看运行时行为
- `UDynamicMeshComponent` 默认是 `NoCollision`，要手动 `SetCollisionEnabled` + `EnableComplexAsSimpleCollision`
- 复杂碰撞是逐三角形求交，石头多了会卡，以后要换简化碰撞
- 编辑 `DigVolume.*` 这类含中文的文件后，要**确认 UTF-8 BOM 还在**（编辑工具会吃掉它）
- 判断编译是否真的成功：看 `Result: Succeeded` + `Binaries/Win64/UnrealEditor-study.dll` 的时间戳
